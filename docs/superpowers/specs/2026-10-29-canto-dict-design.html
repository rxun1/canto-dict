canto-dict — Design Spec

Date: 2026-10-29 Status: Approved in brainstorming; awaiting written-spec review

1. Goal

A personal iPhone app (React Native / Expo) that:

  1. Looks up Cantonese characters (字) and words (詞) offline, showing Jyutping (e.g. sik6), a Mandarin meaning, example sentences, and real-person pronunciation audio.
  2. Translates a Mandarin sentence into Cantonese with Jyutping and reads it aloud. Works offline with a rule-based converter; when online, upgrades the result using a free LLM API (Gemini by default).

2. Decisions and constraints

Topic Decision
Audience Personal / sideload only. Non-commercial data (words.hk) is allowed. Nothing is published to an app store.
Platform iPhone only
Stack Expo SDK 58 (expo 58.0.21, React Native 0.88, React 19.3; checked 2026-10-30), dev build via npx expo run:ios --device, Expo Router, TypeScript
Script Input accepted in simplified or traditional. Display in simplified. Characters with no simplified form (嘅, 冇, 喺) display unchanged.
App size < 200 MB. No on-device neural translation model.
v1 extras Search history, favorites, search by Jyutping, example sentences. English is out of scope (no English search, definitions or glosses).
Online translation OpenAI-compatible client. Default preset: Gemini API free tier. Presets for Z.ai GLM-4.7-Flash and Custom. Key stored in the iOS Keychain.
Sentence read-aloud Default: iOS Cantonese voice. Toggle: real-person syllable playback.
Jyutping source Always computed locally (dictionary first, to-jyutping fallback), never taken from an LLM

Research behind these decisions lives in docs/research/: lexical-datasets.html, audio-datasets.html, translation.html, free-llm-apis.html.

4. Data pipeline

Run on the Mac with npm run data:build. Steps: download → parse → merge → validate → build (build also writes the report).

Required vs optional sources. Every source is either required or optional (column below). A required source that fails to download or validate stops the build. An optional source that is missing is skipped and listed as omitted in the build report. An optional source can still feed a required feature: a build without the words.hk dump is a usable reduced build, but it does not meet the example-sentences requirement, and the report says so. Milestone 1 builds a starter dictionary from a smaller required set (rime characters + words, 開放詞典, syllable audio); milestone 2 makes the full required set mandatory.

Reproducible inputs. The build report records each source's URL, version or last-modified date, and SHA-256 checksum.

4.2 Merge rules

  • Normalize every headword key with OpenCC so rime (OpenCC forms) and words.hk (HK forms) join correctly. Store trad and simp for every headword and example.
  • Reading rank from rime (預設 default / 常用 common / 罕見 rare / 棄用 obsolete). LSHK merged "lazy" readings (e.g. m5/ng5) become variant, never default.
  • Strip or translate source-specific markers, e.g. words.hk ! loan-syllable markers.
  • Validate every Jyutping against the syllable inventory, allowing sentence particles (la1, ga3, …).

4.3 canto.db schema

entries     (id INTEGER PK, trad TEXT, simp TEXT, kind TEXT CHECK(kind IN ('char','word')), freq REAL)
aliases     (entry_id, trad TEXT, simp TEXT)  -- other spellings folded into the entry: 這裡 for 這裏, words.hk variant 㨂 for 揀
readings    (entry_id, jyutping TEXT, rank TEXT NULL, source TEXT, loan TEXT NULL)  -- loan: comma-separated 0-based indexes of loan syllables (e.g. es1 in DSE)
mandarin    (entry_id, word_trad TEXT, word_simp TEXT, sources TEXT)  -- sources: comma-separated, priority order (kaifangcidian,wiktionary)
definitions (entry_id, sense INTEGER, pos TEXT NULL, yue TEXT NULL, yue_simp TEXT NULL, zho TEXT NULL, zho_simp TEXT NULL, source TEXT)
examples    (entry_id, sense INTEGER, yue_trad TEXT, yue_simp TEXT, jyutping TEXT NULL, loan TEXT NULL, zho TEXT NULL, zho_simp TEXT NULL, source TEXT)
search_keys (key TEXT, entry_id, type TEXT CHECK(type IN ('toned','toneless','joined')))
-- indexes on entries(trad), entries(simp), aliases(trad), aliases(simp), search_keys(key), and entry_id on every child table

Definitions and examples keep the source's traditional text verbatim plus a simplified copy (OpenCC t2s with the keep-list) that the app displays. MoE (國語辭典) senses are stored only for headwords that matched a Cantonese entry, and their simplified copy is for personal display only (its licence forbids redistributing it converted).

4.4 Audio pack

All syllable clips are re-encoded to 32 kbps mono MP3, with leading and trailing silence trimmed (≤ 20 ms left at -50 dB), and concatenated into syllables.pack (~9.7 MB; the source clips are already 32 kbps mono, ~9.8 MB raw). syllables.json maps jyutping → [offset, length]. Syllables with no clip are listed in the build report.

4.5 Phrase table

Generated by reversing Kaifangcidian + Wiktionary mappings (Mandarin → Cantonese), then merged with a hand-curated list of ~300 high-frequency phrases in src/translate/offline/curated.ts. The curated list wins on conflict.

4.6 Build report

data-pipeline/build-report.html: entry counts per source, reading coverage, audio coverage (types and token-weighted), DB size, and validation warnings. Key numbers are copied onto the dashboard.

5. Lookup

5.1 Input classification and search

Debounced 150 ms; top 50 results.

Input Type Matching
Contains CJK Characters Exact (trad or simp of the entry or one of its aliases) → prefix → contains. An alias hit returns the standard entry once.
Latin with tone digits that splits into valid Jyutping syllables (sik6, sik6 faan6) Jyutping only Prefix on search_keys. Spaces are ignored.
Latin without digits that splits into valid Jyutping syllables (sik, sikfaan, sin) Jyutping (toneless) Prefix on search_keys toneless keys; matches all tones.
Any other Latin text (water) Not searchable No query; show the hint “输入汉字或粤拼” (type characters or Jyutping)

Before classifying, input is NFKC-normalized (full-width ｓｉｋ６ → sik6), trimmed and truncated to 50 characters; blank input runs no query and shows no hint. Pasted separators (-, –, ', ‘, ’) count as spaces, and a lone tone digit joins the previous syllable (sik 6 → sik6). An unfinished last syllable (sikf, nei5 h) is not valid Jyutping, so the hint shows briefly while a multi-syllable query is typed; this is accepted (decided 2026-10-31).

Search keys: toned (sik6faan6), toneless (sikfaan), and joined, the mixed toned/toneless forms of a reading's first 3 syllables with the last of them toned (sikfaan6), so a query that types only some tones still matches. Keys stop before a syllable that is not valid Jyutping (a words.hk loan syllable: DSE di1 es1 ji1 gets di1), so a key can be shorter than its reading.

Ranking: match quality (exact > prefix > contains; for Jyutping, exact compares readings.jyutping with spaces removed, not search_keys.key, which can be a truncated reading) → freq (word frequency; rime’s words dict has no weights, so P1-T13 takes it from another source, e.g. rime-cantonese essay-cantonese.txt) → shorter headword.

5.2 Entry screen

  • Headword in simplified (large) + traditional (small) when different, then a TTS button: iOS speaks the whole word (traditional) with the Cantonese voice. Added 2026-10-31 after QA: TTS sounded good on words of 2+ characters. It may pick another reading of a polyphonic character, so readings keep 🔊. An IPA-forced TTS (AVSpeechSynthesisIPANotationAttribute) sounded wrong with and without tone letters and was dropped (Swift sources kept on branch exp/tts-ipa, commit 2d737be).
  • Each reading with 🔊 (real-person syllables) and its rank tag.
  • Mandarin line, in fallback order: (1) mandarin table equivalents; (2) MoE definition (definitions.zho); (3) words.hk Cantonese explanation, labelled 粤语释义.
  • Definitions by sense, examples with Jyutping, Mandarin and 🔊.
  • For words: each character links to its own entry.
  • ☆ toggles favorite. Opening an entry appends to history.

5.3 Saved

user.db (writable, separate from canto.db):

favorites (entry_id PK, added_at)
history   (id PK, kind TEXT CHECK(kind IN ('lookup','translation')), entry_id NULL, input TEXT NULL, output TEXT NULL, at)

History is newest first and capped at 500 rows, with a Clear button. Tapping a translation reopens it on the Translate tab.

6. Translation

6.1 Flow

translate(text) → { cantonese, jyutping[], source: 'offline' | 'online', note? }

  1. Validate: trimmed, non-empty, ≤ 500 characters.
  2. Offline (always, immediate): OpenCC s2t → phrase table (longest match) → reorder rules → Jyutping via src/jyutping → OpenCC t2s for display. Tagged 离线.
  3. Online (if a connection and key are present, started in parallel): on success, replace the offline result and tag it AI. On failure, keep the offline result and show a note.

6.2 Offline rules (initial set)

Word substitutions (的→嘅, 是→係, 没有→冇, 他/她→佢, 在→喺, 看→睇, 什么→乜嘢, 吃→食, …) plus reorder rules: comparatives (A比B高 → A高過B), 先 placement (你先走 → 你行先), 给我 → 畀我, progressive 在V → V緊, 了 → 咗/喇, A-not-A questions.

6.3 Online client

  • POST {baseURL}/chat/completions (OpenAI-compatible), Authorization: Bearer <key>, 15 s timeout.
  • Presets:
    • Gemini (default): base https://generativelanguage.googleapis.com/v1beta/openai/, model gemini-3.8-flash. On HTTP 429, retry once with gemini-3.5-flash-lite.
    • Z.ai: base https://api.z.ai/api/paas/v4/, model glm-4.7-flash.
    • Custom: user-entered base URL, model and key.
  • Prompt: translate into natural Hong Kong colloquial Cantonese in traditional characters, with few-shot examples. Request JSON {"cantonese": "..."}. If parsing fails, accept raw text only if it contains CJK.
  • The key is stored with expo-secure-store and never logged.

6.4 Read-aloud

  • Default: expo-speech with the first installed voice whose language is yue-HK or zh-HK.
  • Toggle: real-person syllables in sequence, using the displayed Jyutping.
  • Dictionary characters and words always use real-person syllables, except the entry screen's TTS button after the headword (§5.2).

7. Error handling

Situation Behaviour
canto.db fails to open/copy Full-screen error + Retry
Syllable has no clip Speak that character with iOS TTS; show a small "TTS" tag
No Cantonese voice installed Show download steps (Settings → Accessibility → Spoken Content → Voices)
No API key Offline result + hint to Settings
401 "API key invalid" + link to Settings; keep offline result
429 Retry once with the fallback model, then keep offline result
Timeout / bad JSON / no CJK in reply Keep offline result + note
Input > 500 characters Ask the user to shorten it
Pipeline download or validation failure Build stops with a clear message; no partial outputs

8. Testing

  • Unit (Jest, jest-expo): input classifier, Jyutping parser/normalizer, search ranking, offline rules (golden input→output pairs), online client (mocked fetch: 200 / 401 / 429 / timeout / bad JSON), history cap.
  • DB tests: src/db depends on a small Db interface; tests use better-sqlite3 against a fixture DB built by the pipeline from data-pipeline/fixtures/.
  • Pipeline tests: each source parser against fixture files (e.g. Yale → Jyutping).
  • Translation eval: npm run eval:translate prints chrF of the offline converter on the test set; the score is tracked on the dashboard.
  • Device QA checklist: search (characters / Jyutping), syllable and sentence audio, translate in airplane mode, online upgrade replaces the offline result.
  • Development is test-first.

9. Out of scope for v1

  • Android, App Store distribution.
  • English: search by English, English definitions and glosses (dropped 2026-10-30).
  • On-device neural translation models (size budget).
  • Per-word recordings (Lingua Libre / Commons) and Common Voice alignment. Possible v1.x add-on.
  • Cloud TTS (Azure / Google / Polly).
  • Favoriting translations; flashcards; sync across devices.

10. Risks

Risk Mitigation
Gemini free-tier limits or model names change Presets are data, not code; Custom preset; Z.ai fallback
Gemini unavailable in HK / mainland China Z.ai preset works there
Offline translation sounds stiff Labelled 离线; online upgrade; chrF eval to track improvements
to-jyutping uses JS syntax Hermes may not support Verified 2026-10-31 (P2-T2) on the iOS 27.2 simulator under Hermes: to-jyutping 3.1.1 gives 食飯 → sik6 faan6 and opencc-js 1.4.2 (cn → t) gives 学校 → 學校, no transpiling needed. Re-check on the iPhone at the first device run (P2-T12) in a Debug build via Settings → Dev checks (the link is __DEV__-only; in Release open cantodict://dev-checks).
words.hk dump requires a manual request form Pipeline accepts a manually downloaded file path if automated download fails
